## The print behaviour

The page is a working document, so print output was treated as a real output
rather than an afterthought:

- Nav, scroll progress, header, prose, FAQ, CTA, related links, disclaimer and
  footer are all wrapped in `print:hidden`
- The checklist section stays, with a print-only heading (`sr-only
  print:not-sr-only`) and a print-only fill-in line for organisation, completed
  by, date, and the source URL
- Each stage card and each row carries `print:break-inside-avoid` so groups are
  not split across pages
- Type, padding and borders shrink under `print:` so the 27 rows stay readable

No client component was added — this is CSS only, and the article tells the
reader to use Ctrl/Cmd+P. A `window.print()` button would need `"use client"`
on an otherwise fully static route; not worth it.

**This needs a human eye.** Print CSS cannot be verified from rendered HTML.
Someone should open the print preview and confirm the pagination.
